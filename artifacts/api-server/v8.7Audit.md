## 1. Architecture Overview

V8.7 adds a fully deterministic, zero-LLM DevOps & Infrastructure Architect that runs at step **0.7** in the NexoGen build pipeline — after the Backend Architect (step 0.6) and before the Architecture Planner (step 1).

The engine automatically detects the infrastructure type from the backend type, then executes 22 sequential planning phases to produce an immutable `DevOpsBlueprint`. The blueprint is validated across 9 quality dimensions, persisted with version history, fed into the async learning engine, and injected into the downstream Planner prompt.

The DevOps Architect **never deploys infrastructure** — it only produces architecture strategy documents.

## 2. Pipeline Position

```
Product Manager         (step 0)     — classifies goal, personas, features
      ↓
Frontend Architect      (step 0.5)   — 22-file static frontend blueprint
      ↓
Backend Architect       (step 0.6)   — 19-planner static backend blueprint
      ↓
DevOps Architect        (step 0.7)   — 22-phase static devops blueprint      ← V8.7
      ↓
Architecture Planner    (step 1)     — LLM-powered system architecture prompt
      ↓
… remaining 10 pipeline steps …
```

Verified in `buildPipeline.ts`:
- `runDevOpsArchitectStep` is called after `runBackendArchitectStep` and before `runPlannerStep`
- `devopsArchitectOutput.enrichedPromptWithDevOps` is concatenated into the downstream planner prompt
- `devopsBlueprint` and `devopsArchitectureScore` are passed in the `done` SSE event

**No duplicate execution. No skipped execution. Blueprint is passed as a readonly value.**

## 8. Persistence Design (Phase 21)

`devopsPersistence.ts` provides:

| Requirement | Implementation |
|-------------|---------------|
| Max 500 snapshots | `capHistory()` trims oldest when exceeded |
| Version history | Each snapshot is version-numbered (monotonic counter) |
| Rollback | `rollbackDevOpsToVersion(n)` returns blueprint at that version |
| Recovery after restart | In-memory store is always fresh; idempotent `initDevOpsPersistence()` |
| Debounced writes | 300ms debounce timer prevents flush storms |
| Non-blocking | All operations are synchronous in-memory; never throws into pipeline |

---

## 9. Learning Engine (Phase 19)

`devopsLearning.ts` learns from every build:
- `infrastructureType` and `cloudProvider` tracked per record
- `securityScore` and `reliabilityScore` extracted from qualityScores
- `improved` flag set when same infra+provider pair shows score improvement
- Max 200 records (separate from persistence's 500-snapshot store)
- Always **asynchronous** (fire-and-forget Promise) — never blocks builds
