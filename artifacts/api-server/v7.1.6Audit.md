## Feature summary

V7.1.6 introduces a real-time per-component performance tracking system that feeds back into the build pipeline. Every generated page's component selections are scored on four dimensions and the rankings are used to steer future selections away from underperforming components.

## Quality score formula

```
qualityScore = designScore × 0.40
             + accessibilityScore × 0.25
             + (successRate × 10) × 0.20
             + ((1 − repairRate) × 10) × 0.15
```

All sub-scores are on a 0–10 scale.

- **designScore** = (heroScore + layoutScore + ctaScore + shadcnScore + consistencyScore) / 5  
- **accessibilityScore** = from the design evaluator  
- **successRate** = builds where `repairApplied = false` / total uses  
- **repairRate** = builds where `repairApplied = true` / total uses

---

## Auto-deprecation logic

A component is marked **deprecated** when, after ≥ 3 uses:
- `repairRate > 50%` AND `qualityScore < 6.0`

A deprecated component is **rehabilitated** when:
- `repairRate ≤ 30%` AND `qualityScore ≥ 7.0`

## Pipeline changes

### `designEvaluatorStep.ts`
- Imports `recordComponentBuildResult` from `quality/componentMetrics.ts`
- After evaluation, extracts component IDs from `frontend.registrySelection`
- Calls `recordComponentBuildResult()` with design/a11y/overall scores and repair status
- Adds `componentsUsed` field to `EvaluatorResult` and output

### `frontendStep.ts`
- Imports `isComponentDeprecated`, `getBestAlternativeInCategory`
- After `selectRegistryComponentsServer()`, checks each selected component for deprecation
- Deprecated components are swapped with the best non-deprecated alternative in the same category
- If no alternative exists, the category hint is removed (falls back to DNA codegen)
