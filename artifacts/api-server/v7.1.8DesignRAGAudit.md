## Retrieval

### Ranking algorithm (per-reference composite score)

| Factor | Weight | Notes |
|--------|--------|-------|
| Industry match | +3 per match | compares ref.industry vs detected industries |
| Style match | +5 | ref.style includes input.style from DNA |
| DNA secondary brand | +2–4 | non-dominant brand ≥20% also considered |
| Keyword match | +2 per match (max 6) | ref.tags + description vs prompt tokens |
| Category bonus | +6 | ref.category is in blueprint.sectionOrder |
| Baseline quality | qualityHint × 0.5 | 0–10 → 0–5 points |
| Live quality boost | +2 | componentMetrics quality > 8 |
| Deprecation penalty | −10 | any componentId deprecated in componentMetrics |

Deduplication: no two results share the same `(category, layout)` key.  
Returns: top 5 references, sorted by score descending, then ID for determinism.

### Quality integration (Phase 3)
- Reads live component quality scores from `componentMetrics.ts`  
- Deprecated components penalized −10 points  
- High-quality components (score > 8) get +2 boost

## Planner integration (Phase 4)

**Exact injection point:** `artifacts/api-server/src/agents/pipeline/frontendStep.ts`  
After registry selection + deprecation filtering, before codegen call.

`extractRetrievalIntent(prompt, blueprint.sectionOrder, design.designLanguage, dnaComposition)`  
→ `retrieveDesignReferences(intent)`  
→ `buildRetrievalContext(result)` → injected into codegen system prompt as appended block

---

## Frontend integration (Phase 5)

**Exact injection point:** same file, `runFrontendStep`, codegen call at step 3.

Retrieval context is appended to `buildCodeSystem(...)` output:
```
${codeSystemContent}\n\n${retrievalContext}
```
If retrieval fails (try/catch), codegen proceeds normally with empty context.

`FrontendOutput` now carries: `retrievalContext: string`, `retrievalReferenceIds: string[]`

## Telemetry (Phase 7)

`GET /telemetry/quality` now returns `retrieval` field:

```json
{
  "retrieval": {
    "retrievalCount": 42,
    "retrievalHitCount": 42,
    "retrievalHitRate": "100.0%",
    "referencesUsed": 210,
    "retrievalQualityAverage": 9.05,
    "topStyles": [...],
    "topCategories": [...]
  }
}
```

Metrics tracked in `qualityMetrics.ts` via `recordDesignRetrieval()` called from `retriever.ts`.  
Counters also increment `globalMetrics` (`rag.retrievalCount`, `rag.retrievalHit`).

## Remaining Gaps

- `retrievalImpactScore` is the final score, not a delta vs no-RAG baseline. A true A/B comparison would require running each build twice (with and without RAG), which would double build cost.
- `topStyles` in retrieval telemetry shows style frequency, not style improvement. Quality improvement tracking requires a longer-running history of builds.
