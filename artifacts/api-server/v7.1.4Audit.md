## Evaluator Active?

**YES**

`buildPipeline.ts` calls `runDesignEvaluatorStep()` between `runRepairStep()` and `runBackendStep()`:

```typescript
const evaluatedFrontend = await withAgentMetrics("DesignEvaluator", () =>
  runDesignEvaluatorStep(repairedFrontend, keys, res)
);
const backend = await withAgentMetrics("Scaffold", () =>
  runBackendStep(architecture, evaluatedFrontend, keys, res)
);
```

The SSE `done` event now uses `evaluatedFrontend.fixedCode` (improved code if repair ran).

## Repair Loop Active?

**YES**

`designEvaluatorStep.ts` runs a `while` loop bounded by:
- `evalResult.overallScore < 8.0` (threshold)
- `repairCount < MAX_DESIGN_REPAIR_PASSES` (max 2)
- `break` on any repair error

Terminates after maximum 2 LLM calls to `runDesignRepair()`.

## Remaining Quality Gaps

**Verified findings only — no speculation:**

1. **Shadcn score on text-heavy pages** — The `shadcnScore` check requires `<Card>` and `<Badge>`. Pages with only text content (e.g. blog-style) may score low despite valid design. This is by design (shadcn-first policy) but could penalize legitimate non-card layouts.

2. **Background alternation detection range** — The `bg-[#hex]` regex only catches hardcoded hex colors. CSS variables (`bg-background`, `bg-surface`) are not detected. Pages using design token class names may score lower on layout alternation than they deserve.

3. **Hero trust signal regex breadth** — Trust signal detection covers ★, AvatarImage, user counts, and uptime. Logo cloud components with arbitrary structure (e.g. a `div.logos-row`) may not be detected by the current regex.

4. **Repair output verification** — The repair agent returns improved code but the `projectFiles` array is not updated (only `fixedCode` is updated). The multi-file preview tree continues to show the pre-repair version of individual files.

5. **No pre/post repair score comparison in `done` event** — The `done` SSE includes `evaluatedFrontend.fixedCode` but does not include `evaluationResult`. The frontend client cannot display the final design score in the build UI without reading the `design_eval_result` SSE event separately.
