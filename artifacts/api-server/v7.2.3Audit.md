# V7.2.3 Audit — Section Outcome Feedback Loop

## Learning System

**Is section learning active?**
YES. `recordSectionOutcome()` is called from `designEvaluatorStep.ts` after every build, passing the final post-repair score. Pre-repair score is never recorded.

**Exact call chain:**
```
designEvaluatorStep.ts → runDesignEvaluatorStep()
  ↓  (after repair loop, using final evalResult)
  ↓  for each refId in frontend.retrievalReferenceIds
  ↓    normalizeSectionType(refId) → SectionType | null
  ↓    recordSectionOutcome({ referenceId, sectionType, overallScore, heroScore,
  ↓                           layoutScore, ctaScore, accessibilityScore,
  ↓                           consistencyScore, repairTriggered })
  ↓    → sectionReferenceMetrics.ts: updates running averages, qualityScore,
         triggers promotion/demotion check
```

**When are outcomes recorded?**
After the Design Evaluator AND after the Repair Loop. Only the final `evalResult.overallScore` is used. The pre-repair `initialScore` is NEVER passed to `recordSectionOutcome()`.

---

## Promotion

**Conditions:**
- `usageCount >= 5` (minimum sample)
- `avgScore >= 9`
- `repairRate < 0.15` (< 15%)

**Bonus:** +1.5 to qualityScore, capped at 10.

**Reversible?**
YES. `applyPromotionDemotion()` runs on every outcome. If avgScore drops below 9 or repairRate rises above 15%, priority reverts to `'normal'` (or `'demoted'` if conditions are worse).

---

## Demotion

**Conditions:**
- `usageCount >= 5` (minimum sample)
- `avgScore < 7` OR `repairRate > 0.50`

**Penalty:** −2.0 to qualityScore, floored at 0.

**Reversible?**
YES. Identical re-evaluation on every outcome. If avgScore recovers above 7 AND repairRate drops below 50%, priority reverts to `'normal'` (or `'promoted'` if thresholds are met).

---

## Retriever

**Is quality score live?**
YES. `sectionRetriever.ts` calls `getSectionQualityScore(ref.id)` during `scoreSectionRef()` for every candidate reference at retrieval time.

**Weight calculation:**
```
SECTION_LEARNING_W = 1.6
contribution = (qualityScore − 5) × 1.6   →   range −8..+8
```

Theoretical max baseline (DNA + industry + style + keywords + quality) ≈ 40.  
Max learning contribution: 8 / (40 + 8) ≈ **17%** (≤ 20% as specified).  
Neutral references (score = 5) contribute exactly 0.  
DNA weight (STYLE_W=6 + DNA_W=4 = 10) always > max learning boost (8).

## Remaining Gaps

**Persistence:** All metrics are in-memory. A server restart resets all learned quality scores. References will restart at neutral (5.0) and re-learn from new builds. No data loss in production as the system is designed for session-level learning.

**Section type derivation from refId:** `normalizeSectionType(refId)` derives section type from the reference ID string (e.g. `"hero-split-text"` → `'hero'`). Reference IDs that do not match any known section type prefix are silently skipped (no outcome recorded). This affects: `navbar-*` and `dashboard-*` references — `normalizeSectionType` correctly handles both since SECTION_ALIASES maps both aliases.

**Cold-start:** New references with no outcomes use quality score 5.0 (neutral). No bias for or against new references. System reaches meaningful signal after 5+ outcomes per reference.
