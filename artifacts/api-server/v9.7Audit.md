## 4. Planner Responsibilities

### Phase 1 — Goal Analysis
Detects 10 goal dimensions from prompt keywords:
- **Business**: SaaS, revenue, subscription, marketplace, startup, platform
- **Technical**: API, database, backend, microservice, deploy
- **UX**: dashboard, modern, responsive, intuitive, landing
- **Performance**: fast, cache, CDN, lighthouse, core-web-vitals
- **SEO**: seo, organic, sitemap, blog, traffic
- **Security**: auth, login, JWT, OAuth, RBAC, GDPR
- **Scalability**: enterprise, scale, horizontal, queue, multi-tenant
- **Accessibility**: WCAG, aria, screen-reader, keyboard, a11y
- **Analytics**: analytics, tracking, KPI, chart, funnel
- **Maintenance**: tests, CI/CD, lint, observability

### Phase 2 — Requirement Extraction
Auto-detects from prompt:
- Pages (landing, dashboard, auth, profile, settings, admin, pricing, blog, etc.)
- Layouts (root, app-shell, marketing, auth, docs)
- Components (navbar, sidebar, data-table, chart, modal, hero, pricing-table, etc.)
- APIs (auth, users, products, orders, payments, notifications, search, analytics, upload)
- DB tables (users, sessions, products, orders, payments, notifications, events, content, teams, roles)
- 12 boolean feature flags (authentication, authorization, dashboard, adminPanel, cms, payments, etc.)
- User roles (user, admin, moderator, super-admin, member, guest, manager)

### Phase 3 — Feature Dependency Graph
- Static dependency rules (14 rules: dashboard→auth, payments→auth, admin→rbac, etc.)
- DFS cycle detection
- Independent branch detection
- Blocking chains (features with ≥2 dependents)
- Transitive redundant dependency detection

### Phase 4 — Milestone Planning
- M1: Foundation (always; criticalPath=true)
- M2: Authentication (if auth detected; criticalPath=true)
- M3: Core Features (dashboard, profile, settings; criticalPath=true)
- M4: Backend & Integrations (payments, CMS, notifications, analytics)
- M5: Admin & Management (admin panel, reports, feature flags)
- M6: Scale & Deploy (enterprise only; criticalPath=true)
- Complexity multiplier: enterprise 1.5×, standard 1.0×, simple 0.7×

### Phase 5 — Roadmap Planning
- Simple: 2 sprints × 14 days = 28 days
- Standard: 3 sprints × 14 days = 42 days
- Enterprise: 5 sprints × 14 days = 70 days
- Parallel/sequential features extracted from milestone feature sets

### Phase 6 — Feature Planning
- Core: always included (foundation, ui-components, routing) + detected features
- Optional: analytics, search, reports, feature-flags
- Future: enterprise-only (real-time, AI integration, multi-tenancy) + undetected optional
- Blocked: features depending on absent requirements
- Enterprise multiplier: 1.4×, standard 1.0×, simple 0.8×

### Phase 7 — Task Planning
- Per-feature task definitions (3-4 tasks each): frontend/backend/QA/devops/design
- Parallel group assignment (group 0=foundation, 1=auth, 2=core, 3=integrations, 4=optional)
- criticalTasks: foundation + auth + routing tasks

### Phase 8 — Risk Planning
Risk categories: technical, security, architecture, timeline, dependency, performance, compliance
- Always: scope creep, technical debt
- With auth: auth vulnerability, session hijacking
- With RBAC: privilege escalation
- With payments: payment failure, billing logic errors
- Enterprise: architecture bottleneck, DB migration failure, GDPR compliance
- High requirements count: timeline overrun risk

### Phase 9 — Estimation
- LLM tokens: simple 15k, standard 35k + 2k/feature, enterprise 60k + 2k/feature
- Files: simple 10, standard 25, enterprise 50 + pages×1.5 + components×0.5
- Infrastructure: web-server, postgresql, + conditional (session-store, stripe, redis, CDN, LB, email, object-storage)
- Cost: tokens × $0.0000008 + infrastructure ($0.001/$0.002/$0.004)

### Phase 10 — Increment Planning
- Inc-1: Foundation (always)
- Inc-2: Authentication & Core
- Inc-3: Main Product Features
- Inc-4: Integrations (standard/enterprise)
- Inc-5: Scale & Deploy (enterprise only)
- All `independentlyBuildable: true`

### Phase 11 — Feature Priority
5-dimension weighted score: businessValue×0.30, technicalImportance×0.25, risk×0.15, dependencyWeight×0.15, complexity×0.15

### Phase 12 — Implementation Planning
- Sequential: group 0+1 tasks (foundation, auth) + criticalTasks
- Parallel: all group ≥2 tasks, wave-organized
- Fast-track: high-priority, no-dependency tasks (up to 5)
- Critical path: critical + top-priority tasks in order

### Phase 13 — Validation
9 dimensions: requirements, dependencies, roadmap, milestones, tasks, risks, estimation, implementation, completeness. Equal weights produce `overallScore` = `planningScore`.

## 6. Persistence Design

- **Store:** In-memory `Map<version, PlanningSnapshot>`, 500-cap, LRU eviction (oldest deleted)
- **Version:** Auto-increments monotonically starting from 1
- **Snapshot fields:** `{ version, buildId, blueprint (with version assigned), savedAt }`
- **Cap:** 500 snapshots × ~10 KB each ≈ 5 MB max
- **Rollback:** `getPlanningSnapshot(targetVersion)` returns any saved version
- **Thread safety:** Synchronous map operations (single-threaded Node.js)
- **Never throws** — all persistence calls are wrapped in try/catch at the facade level

---

## 7. Learning Design

- **Format:** `PlanningLearningRecord` with 10 fields (planningScore, complexity, featureCount, riskLevel, planningTimeMs, buildSucceeded, roadmapAccuracy, dependencyAccuracy, recordedAt, buildId)
- **Cap:** 500 records, FIFO eviction
- **Async:** `learnFromPlanning()` is async (non-blocking), called via fire-and-forget `.catch(()=>{})`
- **Stats tracked:** averagePlanningScore, averagePlanningTimeMs, buildSuccessRate, averageRoadmapAccuracy, averageDependencyAccuracy, byComplexity breakdown
- **Never blocks pipeline** — finalizePlanningIntelligenceStep() is called after the pipeline build completes

## 12. Future Extension Points

1. **Prompt-to-feature ML model** — replace keyword detection with a lightweight classifier trained on labeled prompts; same interface, no pipeline changes needed.
2. **Historical duration calibration** — feed `actualDurationMs` from completed builds back into `estimationPlanner` to tighten the confidence interval over time.
3. **Cross-build dependency tracking** — if the same project is built multiple times, carry forward the feature dependency graph to enable incremental planning.
4. **Risk threshold enforcement** — wire `risks.overallRiskLevel === 'high'` into `checkBuildLimit` to optionally warn users before extremely risky builds proceed.
5. **PlanningBlueprint → Jira/Linear export** — the `tasks.tasks` array maps 1-to-1 to Jira stories; the milestones map to epics; wire via the existing integrations framework.
6. **LLM-augmented goal analysis** — for enterprise builds, optionally send the goal list through a single fast LLM call to refine goal descriptions (guarded by `complexity === 'enterprise' && hasLLMBudget`).
