## Runtime Strategy

`analyzeRuntime()` maps context to a `RuntimeMode`:

| Condition | Detected Mode |
|-----------|--------------|
| `complexity === 'enterprise'` | `enterprise` |
| `executionMode.includes('quality')` OR `reasoningScore >= 8` | `quality` |
| `complexity === 'simple'` AND `tokenEfficiency >= 0.75` | `fast` |
| Default | `balanced` |

`ResourcePressure` is computed from `tokenEfficiency`:
- `< 0.50` → `high`
- `0.50–0.75` → `medium`
- `≥ 0.75` → `low`

## Learning Design

- **Trigger**: `learnFromAdaptiveResult()` called from `finalizeAdaptiveIntelligenceStep()` after build completes
- **Storage**: In-memory `_records[]` array, capped at 500
- **Fire-and-forget**: `learnFromAdaptive()` is `async` and is `.catch()`-guarded — never blocks pipeline
- **Aggregations**: `buildSuccessRate`, `averageAdaptiveScore`, `timeAccuracy`, `costAccuracy`, `byStrategy`, `byComplexity`
- **Hydration**: `hydrateAdaptiveLearning(records)` for future disk-load integration

---

## Persistence Design

- **Storage**: `Map<version, AdaptiveSnapshot>` in-memory
- **Cap**: 500 snapshots — oldest evicted on overflow
- **Versioning**: monotonically incrementing `_currentVersion`
- **Non-destructive rollback**: `rollbackToAdaptiveSnapshot(version)` returns snapshot without deleting newer versions
- **Never throws**: all methods catch internally and degrade gracefully
- **Debounce**: not needed for in-memory (disk persistence is a future extension point)

## Extension Points

1. **Disk persistence**: `adaptivePersistence.ts` has a stub for debounced writes — extend `saveAdaptiveSnapshot()` to persist to `/tmp/voxai-adaptive/`
2. **Cross-build learning**: Connect `hydrateAdaptiveLearning()` to a disk-loaded snapshot in `index.ts`
3. **Planner integration**: Planner can read `quality.evaluationThreshold` and `quality.candidateCount` directly from `AdaptiveBlueprint` to override defaults
4. **Agent skip enforcement**: Pipeline can consult `agentAdaptation.agentsToSkip` to skip agents beyond what the Orchestrator already skips
5. **Circuit breaker**: `failureAdaptation.circuitBreakerEnabled` can gate retries in `repairStep.ts`
