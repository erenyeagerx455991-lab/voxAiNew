## Overview

V8.4 introduces the **Autonomous AI Product Manager** — a complete product strategy engine that sits at pipeline **step 0** (before the Architecture Planner). It runs on pure heuristic keyword analysis of the user prompt with no LLM calls, completing in <5ms. Its output is prepended to the Planner prompt as structured product context, enabling every downstream engine (Planner, Code Generator, Design Critic, Evaluator, Director) to make product-aware decisions.

VoxAI now thinks like a senior PM from Stripe, Linear, Vercel, Notion, or Figma before writing a single line of code.

## 9-Phase Product Planning Engine

### Phase 2 — Product Goal Detection (22 goals)
Keyword-pattern matching with weighted confidence scoring. Returns `{ goal, confidence }`.

| Goal | Example Keywords |
|------|-----------------|
| LandingPage | `landing page`, `waitlist`, `coming soon` |
| SaaS | `saas`, `web app`, `multi-tenant` |
| Dashboard | `dashboard`, `admin panel`, `control panel` |
| CRM | `crm`, `sales pipeline`, `contact management` |
| AIProduct | `ai tool`, `gpt`, `copilot`, `llm` |
| ECommerce | `e-commerce`, `online store`, `shopify` |
| Healthcare | `clinic`, `doctor`, `patient`, `telemedicine` |
| KnowledgeBase | `knowledge base`, `wiki`, `documentation site` |
| … (22 total) | … |

### Phase 3 — Business Objective Detection (20 objectives)
Ranked keyword matching, goal-based fallback when no signal detected.

### Phase 4 — User Persona Inference (18 personas)
Keyword-based, returns up to 4 personas per build. Defaults by product goal.

### Phase 5 — Feature Planning (26 features)
Combines 4 sources:
- Goal-based base features (e.g., SaaS → Authentication + Dashboard + Settings + Billing + Profile)
- Business objective additions (e.g., Subscriptions → + Billing + Payments + Notifications)  
- Prompt keyword detection (26 regex rules)
- Persona additions (e.g., Enterprise → + Teams + Permissions + AuditLogs)
- Deduplication; marketing goals (LandingPage, Portfolio) strip app-heavy features

### Phase 6 — Information Architecture
Generates: pages, sections, navigation, sidebar, footer, settings structure, content hierarchy, feature relationships, dependencies.

### Phase 7 — User Journey Planning (10 stages)
EntryPoint → PrimaryFlow → SecondaryFlow → Onboarding → Activation → Conversion → Retention → UpgradeFlow → SupportFlow → ExitFlow.

### Phase 8 — Monetization Intelligence
Strategies: Freemium | Subscription | OneTime | Enterprise | Usage | Free | None.
Includes: free/pro/enterprise plan items, pricing table flag, feature gates, usage limits, trial flow.

### Phase 9 — Product Roadmap
MVP (first 5 features) → Phase 2 → Phase 3 → Future Features → Nice-to-Have → Technical Priorities → Business Priorities.

### Phase 10 — Risk Detection (13 risk types)
Automatically flags: MissingCTA, MissingPricing, WeakOnboarding, WeakNavigation, FeatureOverload, PoorInformationHierarchy, PoorTrust, MissingAuthentication, WeakDashboard, WeakEmptyStates, WeakErrorStates, MissingLoadingStates, MissingUpgradeFlow.

### Phase 11 — Product Quality Scoring (11 dimensions)

| Dimension | Weight | Key Signal |
|-----------|--------|-----------|
| businessValue | 0.15 | CTA, pricing, analytics |
| userValue | 0.15 | Onboarding, AI features, UX copy |
| featureCompleteness | 0.12 | Feature count vs. goal |
| navigation | 0.10 | Nav clarity, search |
| scalability | 0.08 | Teams, Permissions, AuditLogs |
| productSimplicity | 0.10 | Feature count, overload risk |
| monetization | 0.10 | Billing, pricing, upgrade flow |
| retention | 0.07 | Notifications, Dashboard, Chat |
| activation | 0.07 | Onboarding, notifications |
| growthPotential | 0.04 | Analytics, exports, search |
| enterpriseReadiness | 0.02 | Teams + Permissions + AuditLogs |

**Weight sum: exactly 1.00**

## Learning Loop

1. `learnFromProduct()` called in `setImmediate` (fire-and-forget)
2. Maps product score → conversionScore proxy
3. Feeds into Design DNA via `learnFromBuild()`
4. Records buildId, productGoal, businessObjective, score, risks, features
5. Debounced 30s save to disk

## Pipeline Safety

- Product Manager step catches all errors and returns a fallback `ProductPlan` with neutral scores
- Fallback never emits progress/complete events; SSE stream continues uninterrupted
- `contextString` is empty string on fallback → Planner receives original prompt unchanged
