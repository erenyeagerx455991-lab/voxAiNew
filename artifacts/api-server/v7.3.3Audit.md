## Summary

V7.3.3 introduces a complete Design Token Layer that sits between the Component Tree Planner and the Frontend Generator. Tokens are now the single source of truth for all styling decisions: colors, radius, shadows, spacing, typography, and motion.

| `rounded-2xl` | ✅ | hardcoded_radius |
| `shadow-lg` | ✅ | hardcoded_shadow |
| `var(--primary)` | ✅ | allowed (no violation) |
| `:root { --primary: ... }` | ✅ | allowed (token definition) |

### Scoring Formula
```
penalty = min(8, colorViolations × 0.2 + radiusViolations × 0.1 + shadowViolations × 0.1)
tokenQualityScore = max(0, 10 - penalty)
```

## Remaining Gaps

1. **Phase 12 (Registry):** Existing 60+ premium registry templates still contain hardcoded Tailwind colors. The validator now detects them, but retroactive migration is a V7.4.0 task.
2. **Runtime CSS injection:** The CSS variable block is currently injected into the codegen *prompt* as context, not directly into the generated HTML. The LLM must still choose to use `var()` in its output.
3. **Candidate B/C token enforcement:** Candidates B and C inherit the token context from frontendStep, but their codegen calls inside `candidateSelectionStep.ts` do not yet separately re-inject the tokenCtx. This is safe since they use the same LLM instructions, but explicit enforcement is a V7.3.4 improvement.
