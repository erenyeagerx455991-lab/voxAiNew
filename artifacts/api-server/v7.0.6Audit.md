## Provider Budget

### Is checkProviderBudget live?

**YES.**

`src/agents/llm/aiService.ts` — inside `callAI()` for-loop over `MODEL_CHAIN`:
```
const budgetCheck = checkProviderBudget(PROVIDER);
if (!budgetCheck.allowed) { throw { code: "PROVIDER_BUDGET_EXCEEDED", ... } }
```
This fires BEFORE every outbound `fetch()`. No request may escape without passing this gate.

Validated by: `providerBudgetPreflight.test.ts` — "fetch() never executes when global token budget is exceeded"
Validated by: `providerBudgetGate.test.ts` — test 9 "checkProviderBudget fires before fetch"

### Can RPM trigger?

**YES.** `checkProviderBudget()` checks `s.rpmWindow.length >= MAX_RPM[provider]` after purging stale entries.
`recordProviderRequest()` adds to RPM window before every outbound request.

Validated by: `providerBudgetGate.test.ts` — test 1 "OpenRouter blocked when RPM limit reached"
Validated by: `providerBudgetPreflight.test.ts` — "fetch() never executes when RPM limit is exceeded"

---

### Can TPM trigger?

**YES.** `checkProviderBudget()` checks `sumTokens(s.tpmWindow) >= MAX_TPM[provider]`.
`recordProviderTokens()` adds to TPM window after every successful response.

Validated by: `providerBudgetGate.test.ts` — test 2 "OpenRouter blocked when TPM limit reached"
Validated by: `providerBudgetPreflight.test.ts` — "fetch() never executes when TPM limit is exceeded"

---

### Can emergency shutdown trigger?

**YES.** `recordTokenUsage()` (called via `recordProviderTokens()`) sets `_emergencyShutdown = true` when daily usage reaches `emergencyShutdownThreshold` %.
`checkTokenBudget()` (called by `checkProviderBudget()`) returns `{ allowed: false }` when `_emergencyShutdown` is true.

Validated by: `providerBudgetGate.test.ts` — test 6 "Emergency shutdown triggers when daily budget threshold exceeded"

## Edit Limits

### Are edits quota protected?

**YES.** Three routes hardened in `src/routes/agents.ts`:

| Route | Lines Added | Validated By |
|---|---|---|
| `POST /agents/edit` | `checkBuildLimit(userId)` + `checkTokenBudget()` + `recordBuildStarted/Completed` | `editQuota.test.ts` tests 1–5 |
| `POST /agents/runtime-repair` | same | `editQuota.test.ts` test 6 |
| `POST /agents/autonomous-build` | same | `editQuota.test.ts` test 7 |

### Which limits apply?

All four limits from `checkBuildLimit()` [userLimits.ts:54]:
1. `maxActiveBuildsConcurrent` — concurrent builds cap
2. `maxQueuedBuilds` — queue depth cap
3. `dailyBuildQuota` — builds/day
4. `dailyTokenQuota` — tokens/day

Plus global `checkTokenBudget()` [tokenBudget.ts:75]:
- Daily/monthly Groq+OpenRouter token limits
- Emergency shutdown

## Remaining Verified Gaps

**None.** All source-verified gaps from V7.0.4 audit have been resolved:
- Provider budget pre-flight: ACTIVE
- Provider token recording: ACTIVE
- Dead path removed: CONFIRMED
- Streaming token accounting: VERIFIED
- Edit quota bypass: REMOVED

The only known limitations (by design, not gaps):
- `tokenContext` AsyncLocalStorage is not populated for direct edit/repair routes (they bypass the queue). Token quota for these routes is enforced at route entry via `checkBuildLimit(userId)` reading `s.dailyTokens`. This is correct behavior.
- `chat/stream` and `chat/code` do not have quota enforcement — these are lightweight plan-only endpoints with no multi-step LLM loops.
