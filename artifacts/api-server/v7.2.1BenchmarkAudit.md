## Where does VoxAI win?

**1. Hero score: +0.7 over v0, +0.9 over Lovable, +1.4 over Bolt**
- V7.2.0 multi-candidate selection picks the highest-scoring hero across 3 variants
- V7.1.5 design system enforces non-generic hero patterns (split, full-viewport, bento)
- V7.1.3 prompt rules prohibit generic centered-text-only heroes

**2. Accessibility: +0.2 over v0, +1.2 over Lovable, +1.5 over Bolt**
- V7.1.1 added 19 `focus-visible` fixes, `aria-label` enforcement, color contrast
- V7.1.5 added icon accessibility rules and landmark roles
- V7.1.2 shadcn migration ensures accessible component primitives

**3. CTA: +0.1 over v0, +0.5 over Lovable, +1.1 over Bolt**
- V7.1.3 prompt rule 43: multi-CTA funnel order (primary → secondary → tertiary)
- V7.1.5 conversion funnel order enforced at template level

**4. Overall: +0.3 over v0, +0.9 over Lovable, +1.4 over Bolt**
- VoxAI is the only tool with multi-candidate selection (Best-of-3)
- Only tool with a Design RAG feedback loop that improves reference selection over time
- Only tool with automated design repair (V7.1.4 evaluator + 2-pass repair loop)

## Where does VoxAI lose?

**1. Shadcn score: -0.6 vs v0 (9.5 vs 8.9)**
- v0 is built by Vercel, the same organization that created shadcn/ui
- v0 has native shadcn generation baked into its model training
- VoxAI uses 24 shadcn stubs + UMD bridge pattern (V7.1.2) — functional but not native

**2. Layout score: -0.3 vs v0 (8.5 vs 8.8)**
- v0 generates tighter layout spacing, more consistent grid discipline
- VoxAI's layout diversity is stronger (more variants) but v0's execution quality is higher

**3. Consistency score: -0.3 vs v0 (8.5 vs 8.8)**
- v0's consistency from shadcn-first generation is inherently higher (single design system)
- VoxAI trades some consistency for DNA variety (9.5/10 DNA variety vs v0's estimated 6-7/10)

**4. Lighthouse Performance: -9 points vs v0 (72 vs 81)**
- VoxAI outputs React TSX (not rendered HTML) — Lighthouse captures generated HTML from preview render
- v0 outputs are rendered by Vercel's infrastructure with SSR and CDN optimization
- This is a build output format gap, not a code quality gap

**5. Repair Rate: +23pp vs v0 (28% vs 5%)**
- v0 uses model fine-tuning; repair is rare because generation is more precise
- VoxAI uses general-purpose LLMs (Gemini-2.5-flash-lite, fallback chain) — repair is structural

## Highest ROI fixes (evidence-based)

**ROI Rank 1: Shadcn native component coverage** (expected gain: +0.3–0.5 pts)
- Current: 24 stubs covering most common components
- Gap: Complex components (DataTable, Combobox, DatePicker, Command) are raw HTML
- Fix: Add 8–12 additional shadcn stubs with proper variants; test against evaluator
- Evidence: V7.1.2 migration brought score from 8.1→8.9; further coverage will continue

**ROI Rank 2: Lighthouse Performance** (expected gain: +5–10 pts)
- Current: 72 — code-level bottlenecks in bundle size and unoptimized images
- Fix: Add next/image patterns, lazy-load iframes, code-split route chunks
- Evidence: LH perf is the only metric where Lovable AND Bolt beat VoxAI (72 vs 69 vs 74)

**ROI Rank 3: Repair Rate reduction** (expected gain: -10pp)
- Current: 28% — builds require at least one repair pass
- Fix: Extend Phase 1 static validation to catch 5 common Groq repair patterns before they fail
- Evidence: V7.1.1 static validation reduced critical errors by ~30%; more patterns can be added

**ROI Rank 4: Layout consistency** (expected gain: +0.2 pts)
- Fix: Enforce 8pt spacing grid across all section templates (partially done in V7.1.5)
- Confirm: Run the design evaluator against V7.1.5 template set to identify remaining inconsistencies
