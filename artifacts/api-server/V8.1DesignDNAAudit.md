## 1. Architecture

V8.1 adds a **continuously-learning design intelligence layer** on top of the existing V7.x–V8.0 pipeline. It is a pure additive extension: no existing APIs, SSE contracts, BuildContext, or pipeline steps were removed or changed.

### New Modules (`artifacts/api-server/src/design-dna/`)

| File | Role |
|---|---|
| `dnaTypes.ts` | Full DNA record schema, V8.1 quality formula (`computeV81Quality`), confidence formula |
| `dnaRegistry.ts` | In-memory CRUD store for `DesignDNARecord` objects |
| `dnaRanking.ts` | Continuously-updating ranked lists for 21 design categories |
| `dnaVersioning.ts` | Immutable version snapshots with rollback support |
| `dnaPersistence.ts` | JSON file persistence to `/tmp/voxai-dna/snapshot.json` |
| `designDNA.ts` | Facade/manager — all pipeline code calls only this file |
| `dnaLearning.ts` | *(pre-existing V7.3.5)* Per-dimension outcome recorder — unchanged |
| `dnaMetrics.ts` | *(pre-existing V7.3.5)* Per-dimension metrics store — unchanged |
| `dnaEvolution.ts` | *(pre-existing V7.3.5)* Pattern and insight tracker — unchanged |

## 2. Data Flow

```
Build Request
    │
    ▼
[Existing V8.0 13-step Pipeline]
    │
    ▼
sse(res, { type: "done", ... })   ◄── SSE stream closes here
    │
    └── setImmediate(() => {       ◄── Non-blocking; never delays response
            learnFromBuild(...)
        })
            │
            ▼
        designDNA.ts (facade)
            │
            ├── dnaRegistry.ts  ← createOrUpdate DesignDNARecord
            ├── dnaVersioning.ts ← snapshot + version history
            ├── dnaRanking.ts   ← update ranked lists for 21 categories
            └── dnaPersistence.ts ← scheduleSave (debounced, 5s)
```

The `setImmediate` ensures all learning happens **after** the HTTP response is fully flushed. The build route will never wait for DNA evolution.

## 3. DNA Record Schema (Phase 2)

Each `DesignDNARecord` tracks:

**Identity**: `id`, `name`, `industry`, `brand`, `theme`  
**Profiles**: `motionProfile`, `spacingProfile`, `typographyProfile`, `layoutProfile`  
**Preferences**: `componentPreferences`, `sectionPreferences`, `colorPreferences`, `interactionPreferences`  
**Quality Scores (0–10)**: `evaluatorScore`, `criticScore`, `accessibilityScore`, `performanceScore`, `visualScore`, `conversionScore`, `overallScore`, `rankingScore`  
**Usage Stats**: `usageCount`, `successCount`, `repairCount`, `failureCount`, `averageRepairLoops`  
**Lifecycle**: `lastUpdated`, `createdAt`, `version`, `confidence`, `status`

## 4. V8.1 Quality Formula (Phase 9)

```
rankingScore =
    evaluatorScore    × 0.35   (35%)
  + criticScore       × 0.20   (20%)
  + accessibilityScore × 0.10  (10%)
  + performanceScore  × 0.10   (10%)
  + visualScore       × 0.10   (10%)
  + runtimeStability  × 0.05   (5%)
  + userFeedbackScore × 0.05   (5%)
  + benchmarkScore    × 0.05   (5%)
  ─────────────────────────────
  = 0–10, clamped, rounded to 2dp
```

The existing per-dimension quality formula in `dnaMetrics.ts` (V7.3.5) is **unchanged**. The V8.1 formula operates at the whole-DNA level and feeds `rankingScore`.

**Confidence** grows asymptotically: `confidence = (1 - e^(-n/20)) × successRate`, capped at 1.

## 5. Learning Sources (Phase 3 & Phase 5)

All learning functions live in `designDNA.ts` and are fire-and-forget:

| Function | Source | Key Update |
|---|---|---|
| `learnFromBuild()` | V8.0 pipeline `done` event | All 8 score dimensions via rolling average |
| `learnFromCritic()` | Design Critic agent | `criticScore` ± severity penalty ± repair bonus |
| `learnFromBenchmark()` | Benchmark engine | `rankingScore` via benchmark weight (5%) |
| `learnFromRepair()` | Repair loop | `repairCount`, `averageRepairLoops`, `runtimeStability` |
| `learnFromUserFeedback()` | Explicit rating (1–5) | `userFeedbackScore` normalised to 0–10; section preferences adjusted |
| `learnFromVisualDiff()` | Visual diff engine | `visualScore` minus layout/spacing regression penalties |
| `learnFromRuntime()` | Runtime validator | `performanceScore` via rolling average |
| `learnFromTelemetry()` | Telemetry trend signal | `rankingScore` ± 0.3 trend bonus/penalty |

Every call: (1) updates `DesignDNARecord` in registry → (2) creates a version snapshot → (3) updates relevant ranking categories → (4) schedules a debounced persistence save.

## 6. Ranking Engine (Phase 4)

`dnaRanking.ts` maintains rank tables for **21 design categories**:

`layouts` · `components` · `sections` · `motions` · `tokens` · `themes` · `patterns` · `templates` · `forms` · `dashboards` · `navigation` · `heroStyles` · `ctaStyles` · `pricingLayouts` · `faqLayouts` · `footerLayouts` · `cards` · `badges` · `dialogs` · `tables` · `charts`

Each entry tracks: running average score, usage count, success rate, trend (`rising`/`stable`/`falling`). Rankings are updated synchronously on every `learnFrom*` call; reads are O(n log n) sort.

**Convenience getters**: `getTopLayouts()`, `getTopComponents()`, `getTopSections()`, `getTopThemes()`, `getTopMotions()`, `getTopTokens()`, `getTopHeroStyles()`, `getTopCtaStyles()`, etc.

## 7. Evolution Rules (Phase 10)

### Promotion (all 5 criteria must be met simultaneously)

| Criterion | Threshold |
|---|---|
| `rankingScore` | ≥ 9.0 |
| Repair rate (`repairCount / usageCount`) | < 15% |
| `accessibilityScore` | ≥ 9.0 |
| `performanceScore` | ≥ 8.5 |
| `visualScore` | ≥ 9.0 |

### Demotion (any single criterion triggers)

| Criterion | Threshold |
|---|---|
| Repair rate | > 50% |
| `accessibilityScore` | < 7.0 |
| `performanceScore` | < 7.0 |
| Critic severity | `"high"` |
| Visual regression | `layoutRegression === true` (severe) |

**Reversibility**: All status changes are tracked in version history. `rollbackDna(dnaId, version)` restores any previous `DesignDNARecord` snapshot. The rollback itself creates a new version entry to preserve lineage.

## 8. Versioning (Phase 6)

`dnaVersioning.ts` stores immutable version snapshots:
- Every `evolve()` call in `designDNA.ts` creates a `DNAVersion` record
- Up to 50 versions retained per DNA (oldest discarded)
- Each version stores: `versionId`, `dnaId`, `version`, `timestamp`, `changes[]`, `reason`, `previousScore`, `newScore`, `snapshot` (frozen)
- `getVersionHistory(dnaId)` returns all versions oldest-first
- `getRollbackSnapshot(dnaId, version)` returns a mutable copy for restoration

---

## 9. Persistence (Phase 11)

`dnaPersistence.ts` serialises to `/tmp/voxai-dna/snapshot.json`:

**Written**: `dnaRecords[]`, `rankingEntries[]`, `evolutionCount`  
**Schema version**: `"8.1.0"` — forward-compatible; missing fields default gracefully  
**Durability**: Debounced write (5s) — rapid successive builds merge into one file write  
**Failure mode**: Write errors are logged but never propagate; `_persistenceEnabled = false` disables writes if `/tmp` is unavailable  
**Load**: `initPersistence()` is called once at server start; restores all three stores atomically

> **Note**: `/tmp` is not preserved across Replit container restarts. For production durability, replace `dnaPersistence.ts` with a database-backed implementation — the interface is identical.

The V8.1 block is wrapped in `try/catch` — if `getDNAManagerMetrics()` throws for any reason, it falls back to `null` without breaking the telemetry endpoint.

## 11. Performance Impact

| Operation | Cost | Notes |
|---|---|---|
| `learnFromBuild()` | ~0.1ms | Pure in-memory; no I/O |
| `createVersion()` | ~0.05ms | Object freeze + Map append |
| `updateRanking()` | ~0.05ms | Map lookup + arithmetic |
| `scheduleSave()` | ~0ms | Sets a timer; actual write is deferred 5s |
| `saveSnapshot()` (deferred) | ~5–20ms | JSON.stringify + fs.writeFile |
| Telemetry endpoint | +~2ms | Sort + slice operations on Maps |

All learning operations are gated behind `setImmediate` in the pipeline, so **zero build latency is added**.

## 12. Future Extension Path

| Extension | Recommended Approach |
|---|---|
| Database persistence | Replace `dnaPersistence.ts` with a Postgres adapter implementing the same `saveSnapshot/loadSnapshot` interface |
| Cross-session shared DNA | Move registry to a Redis hash; `importRegistry` on startup |
| User-level DNA profiles | Add `userId` to `DesignDNARecord`; `getDnasByUser()` getter in registry |
| RAG retrieval weighting | Call `getTopLayouts()` / `getTopComponents()` in retriever context builders; boost score × (1 + rankingEntry.score / 10) |
| A/B DNA experiments | Add `experimentGroup: "A" | "B"` to the record; compare `rankingScore` distributions after N builds |
| DNA export / sharing | `exportRegistry()` + `exportRankings()` already return serialisable arrays |
| Continuous benchmark integration | Wire `benchmarkMetrics.ts` outcomes to `learnFromBenchmark()` in the benchmark step |
