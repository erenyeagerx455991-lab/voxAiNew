## 1. Architecture Overview

V8.8 adds a fully deterministic, zero-LLM QA & Reliability Architect at pipeline step **0.8** — after DevOps Architect (0.7) and before the Architecture Planner (step 1). It behaves like a Staff QA / Reliability Engineer from Google/Netflix/Stripe/Shopify/GitHub/Microsoft/Amazon/Vercel.

The QA Architect **never generates application features, never deploys infrastructure, and never modifies business logic** — it only produces an immutable `QABlueprint`.

## 2. Pipeline Position

```
Product Manager       (step 0)    — classifies goal, personas, features
      ↓
Frontend Architect    (step 0.5)  — 22-file static frontend blueprint
      ↓
Backend Architect     (step 0.6)  — 19-planner static backend blueprint
      ↓
DevOps Architect      (step 0.7)  — 28-module static devops blueprint
      ↓
QA Architect          (step 0.8)  — 25-module static QA blueprint  ← V8.8
      ↓
Architecture Planner  (step 1)    — LLM-powered system architecture
      ↓
… remaining 10 pipeline steps …
```

`buildPipeline.ts` calls `runQAArchitectStep` after `runDevOpsArchitectStep` and before `runPlannerStep`. `enrichedPromptWithQA` is appended to the combined downstream prompt. `qaBlueprint` and `qaArchitectureScore` are passed in the `done` SSE event.

## 8. Persistence & Learning

- **Max 500 snapshots** — `capHistory()` trims oldest when exceeded
- **Rollback** — `rollbackQAToVersion(n)` retrieves blueprint at any version
- **Debounced writes** — 300ms debounce prevents flush storms
- **Learning** — async fire-and-forget; max 200 records; tracks `byStrategy` distribution
- **Both stores** — completely independent from DevOps/Backend persistence stores
