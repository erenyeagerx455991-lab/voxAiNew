## 2. Workspace Flow

### Mode Lifecycle

```
VIBE MODE (default)
  │ User opens project after AI generation
  ▼
HYBRID MODE (recommended)
  │ User edits any file manually
  ▼
MANUAL MODE (optional)
  │ User takes full ownership
```

### AI → Manual Sync Flow

1. AI generates/regenerates files → `wsMergeAIChanges()`
2. For each file: check if user has manual edits
3. If no manual edits → direct sync (accept AI)
4. If manual edits exist → run `autoMergeNonConflicting()`
5. If auto-merge succeeds → update workspace
6. If conflicts remain → expose `MergeConflict[]` to UI
7. User resolves via Accept AI / Accept Mine / Merge Both / Manual Edit

### Snapshot Flow

```
Before AI Regen → wsCreateSnapshot(trigger='pre-ai')
AI runs → merge
After merge → if conflict → wsCreateSnapshot(trigger='pre-merge')
User resolves → workspace updated → wsCreateSnapshot(trigger='auto')
```

## 4. Merge Engine

### Conflict Detection

The conflict resolver uses a **diff3 heuristic**:

```
For each line i:
  aiChanged   = aiLines[i]   !== baseLines[i]
  userChanged = userLines[i] !== baseLines[i]
  conflict    = aiChanged && userChanged && ai !== user
```

Consecutive conflicting lines are grouped into `MergeConflict` objects with:
- `aiContent` — what AI wants
- `userContent` — what the user wrote
- `baseContent` — what both started from
- `region` — `EditRange` for UI positioning

### Auto-Resolution

Before presenting conflicts to the user, the engine auto-resolves:
- **User unchanged from base** → accept AI (user hasn't touched it)
- **AI unchanged from base** → accept user (AI didn't regenerate it)

Only **true conflicts** (both parties changed from base, differently) reach the user.

### Resolution Strategies

| Strategy | Description |
|---|---|
| `accept-ai` | Replace user content with AI version |
| `accept-mine` | Keep user content |
| `merge-both` | Concatenate both sides |
| `manual-edit` | User writes the resolution |

## 5. Synchronization

### LiveSync State Machine

Each file has a `SyncRecord`:

```typescript
syncStatus: 'synced' | 'diverged' | 'conflict' | 'merging'
editSource: 'ai' | 'manual'
lastAIEdit:  number  // timestamp
lastUserEdit: number // timestamp
```

Global status = worst individual status across all files.

### Sync Operations

| Operation | Trigger | Effect |
|---|---|---|
| `registerAIFile` | AI generates file | Creates sync record |
| `recordUserEdit` | User types | Marks file diverged if AI content exists |
| `planSyncOperation` | Before AI regen | Returns `needsMerge` / `canAutoSync` |
| `markSynced` | After merge | Clears diverged status |
| `markConflict` | Unresolved merge | Sets global conflict status |

## 6. Performance

### Design Principles

- **Lazy evaluation**: workspace state is only computed when requested
- **Incremental updates**: individual file updates, not full workspace rebuilds
- **Capped collections**: every list is capped (snapshots: 500, history: 500, undo: 200)
- **Immutable state**: all planners return new state objects (no mutation)
- **Zero LLM calls**: entire engine is deterministic

### Scalability

| Metric | Supported |
|---|---|
| File count | 10,000+ (Map-based, O(1) lookup) |
| Edit history | 500 per session (ring buffer) |
| Snapshots | 50 in-memory, 500 on disk |
| Terminal sessions | Unlimited (Map-based) |
| Search results | Capped at 200 |
| Symbol extraction | Per-file, cached in state |
| Circular dep detection | DFS, capped at 20 cycles |

## 10. Extension Points

### Adding a New Language

1. Add entry to `EXT_LANGUAGE` in `fileSystemPlanner.ts`
2. Add `LanguageSupport` entry in `codeEditorPlanner.ts`
3. Add lint rules to `lintPlanner.ts` if needed

### Adding a New Refactor Kind

1. Add to `RefactorKind` union in `refactorPlanner.ts`
2. Add analysis in `analyzeRefactorOpportunities()`
3. Add instruction in `buildRefactorAIPrompt()`
4. Add tests

### Adding a New SSE Event

All SSE events in `workspaceStep.ts` are additive — add a new `sendEvent()` call with a unique `type` field. No existing events are modified.

### Adding a New Learning Signal

1. Add field to `WorkspaceLearningRecord` in `manualWorkspaceTypes.ts`
2. Update `learnFromWorkspace()` or `learnFromEdit()` in `workspaceLearning.ts`
3. Update `buildLearningContextString()` to include in AI context

### Adding a New Metric

1. Add counter/accumulator in `workspaceMetrics.ts`
2. Add `record*()` function
3. Include in `getWorkspaceMetricsSnapshot()`
4. The telemetry route picks it up automatically
