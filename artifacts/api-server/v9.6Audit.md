## 1. Overview

V9.6 adds an **Autonomous Execution Intelligence Engine** — the execution brain of VoxAI. It sits between the V9.5 Reasoning Engine and the Planner, converting reasoning decisions into a deterministic, dependency-aware, parallelizable execution plan.

**Reasoning decides WHAT should happen. Execution Intelligence decides HOW.**

## 3. New Capabilities

### 3.1 Task Graph Builder (`taskGraphBuilder.ts`)
- Converts pipeline stages into a 15-task DAG (standard), 9-task (simple), 15-task (enterprise)
- Tasks contain: id, name, dependsOn, priority, estimatedCostTokens, estimatedTimeMs, parallelizable, retryable, timeout, rollbackRequired, isCritical, isBlocking
- Kahn's algorithm produces a valid topological order
- Enterprise builds apply a 1.5× cost/time multiplier

### 3.2 Dependency Resolver (`dependencyResolver.ts`)
- DFS-based cycle detection (detects all cycles, not just one)
- Transitive reach analysis for redundant dependency detection
- Independent branch detection for parallel scheduling opportunities
- Blocking chain detection (tasks with ≥2 direct dependents)

### 3.3 Parallel Planner (`parallelPlanner.ts`)
- Wave-based grouping: tasks at the same topological level can run in parallel
- Produces `parallelEfficiency` (0–1), `idleTimePrediction` (ms saved), `parallelGroups`
- Falls back to sequential order when parallelism is not possible

### 3.4 Critical Path Planner (`criticalPathPlanner.ts`)
- Full CPM (Critical Path Method) implementation: forward pass (earliest finish) + backward pass (latest finish)
- Zero-slack tasks are on the critical path
- Top-3 slowest critical tasks identified as bottlenecks
- Blocking tasks = critical tasks that are `isBlocking`

### 3.5 Priority Planner (`priorityPlanner.ts`)
- 7-dimension priority score: businessValue (0.20), userImpact (0.20), dependencyDepth (0.10), risk (0.15), executionCost (0.10), estimatedDuration (0.10), criticality (0.15)
- Enterprise builds get a 1.1× boost, simple builds get 0.9×
- Maps score to label: critical ≥8, high ≥6, medium ≥4, low <4

### 3.6 Execution Scheduler (`executionScheduler.ts`)
- Derives execution mode from `chosenPath`: A→critical-path-first, C→cost-optimized, B→hybrid/sequential
- Within each wave, tasks sorted by priority score (highest first)

### 3.7 Retry Planner (`retryPlanner.ts`)
- Never-retry list: evaluator, director, ux-intel, conversion, accessibility, optimization, component-tree
- Exponential backoff: repair, runtime-val, scaffold (retryCount=3)
- Linear backoff: planning, architecture, frontend, candidates (retryCount=1)
- `shouldRetry()`: user/validation/config → never; network/timeout/provider → always

### 3.8 Timeout Planner (`timeoutPlanner.ts`)
- Categories: small (<500ms base) → 30s, medium → 2min, large → 5min, enterprise → 10min
- Enterprise builds double all timeouts; simple builds apply 0.8× multiplier

### 3.9 Resource Planner (`resourcePlanner.ts`)
- Estimates: CPU (low/medium/high), memoryMb, llmCalls, apiCalls (3× llmCalls), diskMb=50, networkKb, cacheHits (30%), tempStorageMb=200 (Vite artifacts)

### 3.10 Execution Cost Planner (`executionCostPlanner.ts`)
- Token usage = sum of all task token estimates
- API cost = tokens × $0.0000008/token (blended OpenRouter average)
- Infrastructure cost: enterprise $0.002, other $0.001
- Cost confidence: 1 - |actual-expected|/expected, clamped to [0.3, 1.0]

### 3.11 Execution Time Planner (`executionTimePlanner.ts`)
- minimum = average × 0.7 (optimistic)
- average = max(criticalPathMs, sequential - parallelSavings)
- worst-case = average × 1.6 (retries + slow providers)

### 3.12 Checkpoint Planner (`checkpointPlanner.ts`)
- Inserts after: planning (milestone), frontend (milestone+cost-threshold), repair (milestone), scaffold (milestone)
- High-cost tasks (≥3000 tokens) also get checkpoints
- All checkpoints `supportsResume = true`; rollback-required tasks get `supportsRollback = true`

### 3.13 Resume Planner (`resumePlanner.ts`)
- Supports all 5 resume reasons: crash, restart, timeout, user-pause, deployment-interrupt
- Identifies tasks before last checkpoint as skippable on resume
- Estimates remaining time from last checkpoint

### 3.14 Rollback Planner (`rollbackPlanner.ts`)
- Only rolls back `rollbackRequired=true` tasks in the affected subtree
- Full pipeline restart only if root task fails AND >3 tasks need rollback
- Rollback order = reverse of topological order (latest first)

### 3.15 Failure Recovery Planner (`failureRecoveryPlanner.ts`)
- Identifies failed node + all transitively affected downstream tasks
- Unaffected tasks (independent branches) can continue
- Strategy: retry (retryable), skip (non-retryable leaf), abort (root with many dependents), recover (default)

### 3.16 Execution Validator (`executionValidator.ts`)
- 10 dimensions, 0–10 each, equal-weighted:
  - Task Graph, Dependencies, Parallelism, Critical Path, Retry Strategy, Timeout Strategy, Resource, Cost, Recovery, baseline (7)
- `valid = overallScore ≥ 5 && !hasCycle`

### 3.17 Execution Learning (`executionLearning.ts`)
- Tracks: avgDuration, avgRetries, failureRate, recoveryRate, parallelEfficiency, costPredictionAccuracy, executionSuccessRate
- Per-mode breakdown (count, averageScore, avgDurationMs)
- 500-record rolling cap; fire-and-forget async, never blocks pipeline

### 3.18 Execution Metrics (`executionMetrics.ts`)
- Rolling 500-record metrics; exposes `getExecutionIntelligenceSnapshot()` for telemetry
- `plannerDistribution` tracks mode frequency

### 3.19 Execution Persistence (`executionPersistence.ts`)
- In-memory versioned snapshots, 500-record cap
- `saveExecutionSnapshot()` → version increments; `getExecutionSnapshot(version)` for rollback

## 5. Decision Architecture

```
ReasoningEngine (V9.5)
  → chosenPath: A/B/C
  → confidence, tradeoffs

       ↓

ExecutionIntelligence (V9.6)
  buildTaskGraph()     → 15-task DAG
  dependencyResolver() → cycle/missing/redundant detection
  criticalPathPlanner() → CPM forward+backward pass
  parallelPlanner()    → wave-based grouping
  priorityPlanner()    → 7-dimension score
  executionScheduler() → mode selection + ordered list
  retryPlanner()       → per-task retry config
  timeoutPlanner()     → per-task timeout
  checkpointPlanner()  → milestone + cost-threshold gates
  resumePlanner()      → resumable from last checkpoint
  rollbackPlanner()    → affected-only rollback
  failureRecoveryPlanner() → recovery path
  executionValidator() → 10-dim score
  executionFacade()    → persist + metric + context string

       ↓

Planner (receives enriched prompt with execution context)
```

## 11. Future Evolution Opportunities

1. **Actual duration feedback loop** — wire `actualDurationMs` from `runtimeValidationStep` back into learning to improve cost prediction accuracy over time
2. **Redis-backed persistence** — swap in-memory snapshot store for Redis when `REDIS_URL` is available, enabling multi-instance blueprint recovery
3. **Dynamic re-planning** — if a task exceeds its timeout, trigger `failureRecoveryPlanner` mid-pipeline and adjust the remaining execution order
4. **Budget enforcement** — hook `estimatedCost.totalCost` into the token quota system (`checkBuildLimit`) to reject prohibitively expensive builds upfront
5. **Parallel execution of enrichment tasks** — ux-intel, critic, conversion, accessibility, optimization currently run sequentially; the parallel plan already groups them as the same wave — actual concurrent dispatch awaits Promise.all() wiring in `buildPipeline.ts`
