## Learning Flow

1. `runOptimizationStep` executes synchronously; blueprint returned immediately.
2. After build finishes, `finalizeOptimizationStep` is called by `buildPipeline.ts`.
3. `learnFromOptimizationResult` creates an `OptimizationLearningRecord` and calls `learnFromOptimization(record).catch(() => {})` — fire-and-forget, never blocks.
4. `learnFromOptimization` appends to a rolling 500-record array.
5. `getOptimizationLearningStats` computes: avg score, build success rate, avg build time, time accuracy (estimated vs actual), cost accuracy, breakdown by complexity and model tier.

## Persistence Design

**Strategy:** Versioned in-memory snapshots (no disk I/O — persistence is session-local).

| Property | Value |
|----------|-------|
| Max snapshots | 500 |
| Eviction | Oldest version deleted when cap exceeded |
| Rollback | `rollbackToOptimizationSnapshot(version)` returns any stored snapshot |
| Threading | Single-process in-memory; no locks needed |
| Failure isolation | All persistence calls wrapped in try/catch; never throws into pipeline |

**Snapshot structure:**
```typescript
interface OptimizationSnapshot {
  version:   number;            // monotonically increasing
  buildId:   string;
  blueprint: OptimizationBlueprint;
  savedAt:   number;            // Unix ms
}
```
