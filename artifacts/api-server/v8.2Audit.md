## Prediction Formula

### 17 UX Metrics (0–10 each)

| # | Metric | Description |
|---|--------|-------------|
| 1 | visualClarity | Color contrast, focus indicators |
| 2 | cognitiveLoad | Mental complexity, section count |
| 3 | ctaDiscoverability | Primary CTA prominence and contrast |
| 4 | readingFlow | Heading hierarchy, F-pattern adherence |
| 5 | trust | Social proof, reviews, logos, guarantees |
| 6 | scanningEfficiency | Lists, grids, headings, scannability |
| 7 | navigationSimplicity | Nav link count, logo, mobile menu |
| 8 | formFriction | Field count, labels, validation UX |
| 9 | pricingClarity | Price display, feature comparison, CTA |
| 10 | dashboardUsability | DataTable, charts, skeleton, tabs |
| 11 | informationDensity | Section count, code length, balance |
| 12 | whitespaceBalance | Section padding, gaps, max-width |
| 13 | hierarchy | Heading scale, font weight, text color |
| 14 | accessibilityConfidence | ARIA, focus, alt text, roles |
| 15 | motionComfort | Animation duration, easing, reduced-motion |
| 16 | perceivedPerformance | Skeleton states, loading indicators |

### Overall UX Score Weights (sum = 1.00)

| Dimension | Weight | Notes |
|-----------|--------|-------|
| trust | 14% | Highest UX conversion impact |
| ctaDiscoverability | 14% | Second highest |
| hierarchy | 11% | Visual hierarchy — includes scanning |
| navigationSimplicity | 10% | Core UX pillar |
| formFriction | 10% | Conversion blocker |
| accessibilityConfidence | 10% | WCAG compliance signal |
| whitespaceBalance | 8% | Breathing room |
| informationDensity | 8% | Balance — not too sparse, not too dense |
| visualClarity | 7% | Color, contrast |
| motionComfort | 4% | Comfort / distraction |
| perceivedPerformance | 4% | Loading UX |
| **Total** | **100%** | |

*Note: cognitiveLoad, readingFlow, scanningEfficiency, pricingClarity, dashboardUsability contribute via behavior predictions and page-type detection but are not in the primary weighted sum.*

### Conversion Prediction Formula

```
conversionSignal = trust×0.30 + ctaDiscoverability×0.25 + formFriction×0.20 + hierarchy×0.15 + overallUXScore×0.10

Very High → signal ≥ 8.5
High      → signal ≥ 7.0
Medium    → signal ≥ 5.0
Low       → signal ≥ 3.0
Very Low  → signal < 3.0
```

## Evaluator Weight Redistribution (Phase 6)

Adding `uxPredictionScore` as the 16th evaluator dimension.

**Redistribution:**
- uxPrediction: +0.04 (sourced from: hero −0.01, layout −0.01, accessibility −0.01, navigation −0.01)
- Applied at step level in `designEvaluatorStep.ts` (not in `evaluateDesign()`) because `evaluateDesign()` is a pure static function without UX data

**Formula:**
```typescript
overallScore = evalResult.overallScore * 0.96 + uxPredictionScore * 0.04
// Only applied when uxReport is present (UX step ran)
// When absent: overallScore unchanged (backward compatible)
```

## Candidate Selection Weight Redistribution (Phase 8)

**Before (V7.3.4):** 70% evaluator + 30% visual  
**After (V8.2):** 65% evaluator + 25% visual + 10% UX

**Tie-break priority:**
1. combinedScore (highest wins)
2. uxScore (V8.2 — new first tie-break)
3. visualScore (was first tie-break)
4. accessibilityScore
5. shadcnScore
6. consistencyScore

**Spec validation:**
- Design 9.0 + UX 9.8 vs Design 9.2 + UX 7.4 (visual=8 for both):
  - A: 9.0×0.65 + 8×0.25 + 9.8×0.10 = 5.85+2.00+0.98 = **8.83** ✓
  - B: 9.2×0.65 + 8×0.25 + 7.4×0.10 = 5.98+2.00+0.74 = **8.72** ✓
  - A wins ✓

## Learning Flow (Phase 11)

| Event | Learning Call | Effect |
|-------|---------------|--------|
| Build completes | `learnFromUX()` | Updates DNA via `learnFromBuild()` |
| Repair applied | `learnFromRepairUX()` | Records improved score in DNA |
| Visual diff runs | `learnFromVisualDiff()` | Updates visual/UX correlation |
| Benchmark runs | `learnFromBenchmark()` | Updates DNA baselines |

**DNA update:** `learnFromUX()` calls `learnFromBuild()` mapping UX dimensions to DNA scores:
- `accessibilityScore ← accessibilityConfidence`
- `optimizationScore ← perceivedPerformance`
- `visualScore ← visualClarity`
- `conversionScore ← conversionPrediction (numeric)`
- `success ← overallUXScore >= 6.0`

## Performance

- **UX prediction time:** O(n) where n = code length — typically 1–5ms (no LLM)
- **Memory:** Last 100 runs in-memory telemetry; last 500 in /tmp persistence
- **Pipeline impact:** Adds ~2ms to build (synchronous heuristics only)
- **SSE impact:** 2 new SSE event types (`ux_intelligence_start`, `ux_intelligence_result`) — additive, no existing contract changes
- **DNA learning:** Fire-and-forget via setImmediate — never blocks SSE stream
- **Persistence save semantics:** `learnFromUX()` schedules a debounced disk write (30-second single-fire timer) after every history push. Concurrent calls within the same 30-second window are coalesced into a single write. The save is fully non-blocking — `saveUXSnapshot()` is called via a fire-and-forget `setTimeout` callback with no `await`, so it never delays the pipeline or SSE stream. After the timer fires and clears, the next `learnFromUX()` call begins a fresh 30-second window.

## Future Expansion

1. **LLM-augmented UX scoring** — Run an LLM pass for 1–2 difficult-to-detect UX issues (e.g., microcopy quality, emotional resonance) as an optional enhancement
2. **A/B feedback loop** — Accept real user conversion data to calibrate prediction accuracy

4. **Real-time UX diff** — Track UX score delta across repair passes for granular repair guidance
5. **UX regression alerts** — Flag when UX score drops > 0.5 between builds for same DNA
