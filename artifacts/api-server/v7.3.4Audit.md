# V7.3.4 — Visual Diff Engine & Visual Quality Intelligence Layer

**Date:** 2026-06-25  
**Status:** Complete  
**Tests:** 80+ new (total suite: 1330+ passing)

---

## Summary

V7.3.4 adds a full visual intelligence layer to VoxAI. All visual analysis is **static code-based** — inferred from HTML/JSX/Tailwind class patterns, with no headless browser required. This makes analysis synchronous, deterministic, and zero-latency.

VoxAI evolves from a **Code-Aware Website Builder** to a **Visual-Aware Website Builder**.

---

## Architecture Change

```
Before V7.3.4:
  Generator → Multi-Candidate (A/B/C) → [evaluator score only] → winner → Repair → Critic → Output

After V7.3.4:
  Generator → Multi-Candidate (A/B/C) → [70% evaluator + 30% visual] → winner → Repair
                                                                                ↓
                                                                    Repair Validator (visual regression guard)
                                                                                ↓
                                                               Evaluator (visualQualityScore 16th dim)
                                                                                ↓
                                                               Critic (visual context injected)
                                                                                ↓
                                                                           Output
```

## Visual Score Formulas

### Composite Visual Score
```
visualScore = hero × 0.30 + cta × 0.25 + layout × 0.25 + responsive × 0.20
```

### Hero Score (0–10)
| Check | Points |
|-------|--------|
| `<h1>` headline | 2.5 |
| CTA Button | 2.5 |
| `<p>` description | 2.0 |
| min-h-screen / vh height | 1.0 |
| Badge/pill | 1.0 |
| Trust signal | 1.0 |

### CTA Score (0–10)
| Check | Points |
|-------|--------|
| Primary CTA (variant=default + action words) | 3.5 |
| Secondary CTA (outline/ghost) | 1.5 |
| Click hierarchy (1–4 buttons) | 2.0 |
| Above-fold placement | 2.0 |
| Contrast (bg-primary / CSS var) | 1.0 |

### Layout Score (0–10)
| Check | Points |
|-------|--------|
| Grid or Flex | 2.5 |
| Gap utility | 1.5 |
| Section whitespace (py-16+) | 2.0 |
| Alignment consistency | 1.5 |
| Max-width container | 1.5 |
| Card balance | 1.0 |

### Responsive Score (0–10)
| Check | Points |
|-------|--------|
| Breakpoints (sm:/md:/lg:) | 3.0 |
| Mobile stacking (flex-col) | 2.5 |
| Responsive text | 1.5 |
| Responsive grid | 1.5 |
| No hardcoded pixel widths | 1.0 |
| Mobile nav handled | 0.5 |

## Pixel Diff Algorithm

```
tokenSimilarity  = Jaccard(normalized_tokens_A, normalized_tokens_B)
classSimilarity  = Jaccard(tailwind_classes_A, tailwind_classes_B)
orderSimilarity  = section_order_similarity(sections_A, sections_B)

similarityScore = round((tokenSimilarity×0.4 + classSimilarity×0.4 + orderSimilarity×0.2) × 100)
```

## Candidate Selection Change

**Before (V7.3.3):**
```
winner = max(overallScore)
tie-break: accessibility → shadcn → consistency
```

**After (V7.3.4):**
```
combinedScore = overallScore × 0.70 + visualScore × 0.30
winner = max(combinedScore)
tie-break: visualScore → accessibility → shadcn → consistency
```

### Impact
A candidate with evaluatorScore=7.5 and visualScore=9.0 (combined=8.25) beats a candidate with evaluatorScore=8.0 and visualScore=5.0 (combined=7.1).

## Repair Regression Guard

```
REGRESSION_THRESHOLD = -0.5

if (repairedScore - winnerScore <= -0.5) → VISUAL REGRESSION
if (ctaDrop <= -1.5)                     → CTA REGRESSION
if (layoutDrop <= -1.5)                  → LAYOUT REGRESSION
```

When regression is detected: `passed: false`, `regression: true`, with `regressionType` set.

## Visual Learning Loop

Pattern tracking (min 3 outcomes to promote/demote):
- `hero:badge+headline`, `hero:large-primary-cta`, `hero:social-proof`, `hero:full-height`, `hero:gradient-headline`
- `cta:lg-primary`, `cta:outline-secondary`, `cta:arrow-icon`
- `layout:3-col-grid`, `layout:2-col-grid`, `layout:constrained-max-width`, `layout:generous-section-padding`, `layout:generous-gap`
- `responsive:3-col-breakpoint`, `responsive:mobile-stack`, `responsive:hidden-desktop-nav`

Quality formula: `averageScore×0.6 + winRate×10×0.3 + (1-failRate)×10×0.1`

## Known Limitations

1. **No real pixel comparison** — analysis is code-structure-based. An LLM could generate syntactically correct Tailwind classes that render poorly. V7.3.5 could integrate a real screenshot service (Playwright/Puppeteer in a sidecar).
2. **Hero block extraction** — uses function name matching. Arrow function heroes (const Hero = () => ...) are not extracted; analysis falls back to full-file scan (still correct, just less targeted).
3. **CTA above-fold heuristic** — measures proximity of first `<Button>` to the Hero function definition, not actual rendered position.
4. **Responsive nav score 0.5** — low weight since it's a binary check. V7.3.5 could add sheet/drawer detection.
