# V7.1.9 Audit — Design RAG Feedback Loop + Self-Learning Ranking

## How many references are tracked?

All references that are retrieved during a build are automatically entered into the performance store (`referenceMetrics.ts`). The store starts empty on process start; entries are created lazily on first retrieval. There is no cap — every unique reference ID the retriever returns gets an entry. With the 104-reference corpus in V7.1.8, up to 104 entries can accumulate over time.

Verified: `getStoreSize()` returns the exact count of tracked references at any moment.

## How does ranking change?

**Before V7.1.9 (static):**
```
score = industryMatch + styleMatch + dnaMatch + keywordMatch + categoryBonus
      + baseQuality + liveQualityBoost + deprecationPenalty
```

**After V7.1.9 (self-learning):**
```
score = industryMatch + styleMatch + dnaMatch + keywordMatch + categoryBonus
      + baseQuality + liveQualityBoost + deprecationPenalty
      + getReferenceQualityScore(ref.id) × 0.25   ← V7.1.9 addition
```

`REFERENCE_QUALITY_WEIGHT = 0.25` means a perfect learnt score (10) adds **+2.5 pts** max.

DNA+Style match alone yields **4–9 pts** — it dominates in every realistic scenario. A perfect learnt score on a mismatched reference cannot outrank a correct DNA+style match, satisfying the spec's "DNA match remains dominant" constraint.

New references (no outcomes) receive a neutral score of **5.0**, contributing **+1.25 pts** — a small positive nudge identical for all new entries, so no cold-start bias.

## Dynamic Quality Score Formula

```
qualityScore =
  averageScoreAfterRepair  × 0.40   (0–10 → 0–4.0 pts)
  successRate × 10         × 0.25   (0–1  → 0–2.5 pts)
  (1 – repairRate) × 10    × 0.20   (0–1  → 0–2.0 pts)
  retrievalImpactNorm      × 0.15   (0–10 → 0–1.5 pts)
```

`retrievalImpactNorm = (clamp(avgImpact, −10, +10) + 10) / 2` → maps to 0–10.

Max possible: 4.0 + 2.5 + 2.0 + 1.5 = **10.0** (verified by normalization tests).

Priority adjustments applied after formula:
- Promoted: `min(10, score + 1.5)`
- Demoted:  `max(0,  score − 2.0)`

---

## Promotion Criteria

A reference is **auto-promoted** when ALL of:
- `outcomeCount >= 5`
- `averageScoreAfterRepair >= 9`
- `repairRate < 0.15` (< 15%)

Effect: `priority = 'promoted'`, quality score boosted by +1.5 (capped at 10), `promotedCount++`.

---

## Demotion Criteria

A reference is **auto-demoted** when:
- `outcomeCount >= 5`

AND at least one of:
- `averageScoreAfterRepair < 7`
- `repairRate > 0.50` (> 50%)

Effect: `priority = 'demoted'`, quality score reduced by −2.0 (floored at 0), `demotedCount++`.

## Remaining Verified Gaps

- **Cold-start effect**: New references start with `qualityScore = 5.0` (neutral). After 5+ outcomes they converge to a real learnt score. Builds before the 5th outcome for a given reference see only the neutral baseline boost.
- **In-memory only**: Reference metrics reset on server restart. Persistence to a database would allow cross-deployment learning — not in scope for V7.1.9.
- **Single-process only**: With multiple server instances (horizontal scaling) each instance builds its own store independently. A shared Redis-backed store would be needed for multi-instance convergence — not in scope.
- **retrievalReferenceIds must be populated**: Outcome recording depends on `frontend.retrievalReferenceIds`. If a build skips RAG retrieval this array is empty and no outcomes are recorded — no crash, just no learning for that build.
