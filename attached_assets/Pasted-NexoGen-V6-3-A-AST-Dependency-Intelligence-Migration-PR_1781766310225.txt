NexoGen V6.3-A — AST Dependency Intelligence Migration (PR #1)

Objective

Replace fragile regex-based dependency detection with a real AST-powered analysis engine.

This PR ONLY implements the AST foundation layer.

Do NOT modify UI.

Do NOT modify Runtime Health scoring.

Do NOT modify build pipeline behavior.

Do NOT migrate existing call sites yet.

Focus only on creating a reliable AST analysis engine.

---

Background

Current dependencyResolverV2.ts relies on regex patterns.

Examples:

React hooks:
\buseState\s*[(<]

JSX Components:
<([A-Z][A-Za-z0-9_.]*)[\s/>]

Routes:
<Route[^>]+path=...

This fails on:

- multiline JSX
- nested JSX
- conditional rendering
- HOC wrappers
- TSX generics
- lazy imports
- dynamic imports

Regex must remain fallback only.

AST becomes primary source of truth.

---

Use ONLY:

@babel/traverse

Do NOT use:

- regex as primary parser
- TypeScript Compiler API
- custom string parsing

Parser options:

{
sourceType: "module",
plugins: [
"jsx",
"typescript"
]
}

Must support:

.ts
.tsx
.js
.jsx

Create
