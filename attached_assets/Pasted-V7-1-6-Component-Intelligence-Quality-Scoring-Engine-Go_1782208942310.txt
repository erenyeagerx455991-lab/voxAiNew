V7.1.6 — Component Intelligence & Quality Scoring Engine

Goal

Move VoxAI from:

"Planner selects components by category"

to:

"Planner selects components by proven quality"

Every component should accumulate real performance data.

The planner must automatically prefer the highest-performing components.

---

Phase 1 — Component Metrics Registry

Create:

src/quality/componentMetrics.ts

Track per component:

{
  componentId,
  category,

  usageCount,
  successCount,
  repairCount,

  averageDesignScore,
  averageAccessibilityScore,
  averageOverallScore,

  lastUsedAt
}

Single source of truth.

No duplicate tracking elsewhere.

---

Phase 2 — Capture Metrics After Evaluation

Current pipeline:

Planner
→ Frontend
→ Repair
→ Evaluator

After evaluator completes:

Record:

- final score
- accessibility score
- repair performed (yes/no)

for every component used in the page.

Update component metrics.

Only real builds count.

No synthetic scoring.

---

Phase 3 — Component Quality Score

Create:

qualityScore

Formula:

40% Design Score
25% Accessibility Score
20% Success Rate
15% Repair Rate

Scale:

0–10

Store per component.

---

Phase 4 — Planner Intelligence

Planner should no longer select components randomly.

Selection priority:

1. Highest qualityScore
2. Lowest repairRate
3. Most recent success

Example:

Instead of:

hero-saas-v1
hero-centered-v1
hero-dashboard-v1

random choice

Use:

hero-dashboard-v1 (9.3)
hero-saas-v1 (8.9)
hero-centered-v1 (6.8)

Planner automatically prefers better components.

---

Phase 5 — Category Ranking

Create rankings:

Heroes
Features
Pricing
Testimonials
CTA
FAQ
Dashboard

Each category sorted by qualityScore.

Expose internally.

No UI changes.

---

Phase 6 — Evaluator Integration

Evaluator output should include:

{
  score,
  accessibility,
  repaired,
  componentsUsed
}

ComponentsUsed becomes input for metrics recording.

No additional LLM calls.

---

Phase 7 — Telemetry

Extend existing telemetry.

Add:

componentQuality

Return:

- top components
- worst components
- most repaired components
- least repaired components

No new endpoint.

Extend existing telemetry payload only.

---

Phase 8 — Auto Deprecation

If component:

repairRate > 50%

AND

qualityScore < 6

mark:

deprecated = true

Planner should avoid deprecated components.

Do not delete them.

---

Phase 9 — Benchmark Tests

Create:

tests/integration/componentQuality.test.ts

Verify:

- score calculation
- success tracking
- repair tracking
- ranking
- deprecation
- planner preference

Use real evaluator output.

No mocks hiding logic.

Evidence only.

No estimates.
