NexoGen V6.4.9 — Observability & Telemetry Foundation

Context

V6.4.3 Security Hardening, V6.4.6 Security Baseline, V6.4.7 Test Infrastructure, aur V6.4.8 Pipeline Decomposition complete ho chuke hain.

Current status:

- Security controls active
- 129 tests passing
- 20 contract tests passing
- Build pipeline decomposed into step modules
- /agents/build route reduced to thin orchestrator

However V6.4.5 audit identified major observability gaps:

- 102+ raw console.log calls
- No centralized telemetry storage
- No build duration metrics
- No token usage tracking
- No agent latency tracking
- No repair-loop success metrics
- No request tracing
- No operational dashboard endpoint

This phase focuses ONLY on observability.

No UI redesign.
No AI logic changes.
No prompt changes.
No build pipeline behavior changes.

---

Goals

Create production-grade telemetry system that answers:

1. Which agent is slow?
2. Which step fails most often?
3. How many tokens are consumed?
4. How many repairs succeed?
5. Average build duration?
6. Runtime validation pass rate?
7. Cost trends per provider?
8. Error frequency by category?

Phase 2 — Structured Logging

Audit every console.log / console.warn / console.error.

Replace with centralized logger.

Create:

src/lib/structuredLogger.ts

Supported methods:

logger.info()
logger.warn()
logger.error()
logger.debug()

Every log must include:

timestamp
requestId
workspaceId
projectId
component
event

Example:

{
"event": "BUILD_STARTED",
"workspaceId": "...",
"requestId": "...",
"timestamp": "..."
}

Raw console.log should only remain inside:

- tests
- validation scripts

Nowhere else.
