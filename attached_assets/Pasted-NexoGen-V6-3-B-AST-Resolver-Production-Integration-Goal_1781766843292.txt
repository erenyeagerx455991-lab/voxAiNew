NexoGen V6.3-B — AST Resolver Production Integration

Goal

Integrate the new AST resolver into the existing dependency resolution pipeline.

The AST resolver is already implemented and validated.

DO NOT build new features.

DO NOT modify UI.

DO NOT add new panels, tabs, health dimensions, analytics, scoring systems, or dashboards.

Only replace regex-based dependency detection with AST-based detection.

---

Current State

Implemented:

server/runtime/astResolver.ts

Functions available:

- parseFileAST()
- extractImportsAST()
- extractExportsAST()
- extractHooksAST()

Validation already passes.

Current problem:

dependencyResolverV2.ts still uses regex extraction as the primary source.

The AST resolver exists but is not being used.

---

Objective

Make AST the primary source of truth.

Regex becomes fallback only.

Existing interfaces must remain unchanged.

No breaking API changes.

No frontend changes.

---

Phase 1 — Audit Existing Resolver

Inspect:

server/runtime/dependencyResolverV2.ts

Find every place where regex is used for:

- imports
- exports
- hooks
- routes
- components

Generate a migration checklist before changing code.

---

Phase 2 — Integrate AST Resolver

Import:

server/runtime/astResolver.ts

Replace regex extraction calls with:

extractImportsAST()

extractExportsAST()

extractHooksAST()

AST result becomes authoritative.

Example:

Current:

const imports = extractImportsRegex(content);

Replace with:

const imports = extractImportsAST(content);

---

Phase 3 — Preserve Existing Return Types

Do NOT change public interfaces.

Existing consumers must continue working.

Return shapes must remain identical.

If dependencyResolverV2 currently returns:

{
imports,
exports,
hooks
}

it must still return:

{
imports,
exports,
hooks
}

Only the implementation changes.

---

Phase 4 — Regex Fallback

Keep regex extraction as fallback only.

Flow:

try AST

if AST succeeds:
use AST result

if AST fails:
use regex result

Never throw.

Never interrupt the build pipeline.

Example:

try {
return extractImportsAST(content);
}
catch {
regexFallbackCount++;
return extractImportsRegex(content);
}

---

Phase 5 — Component Detection Migration

Current component detection relies on regex.

Upgrade to AST traversal.

Detect:

- function components
- arrow function components
- memo(...)
- forwardRef(...)
- exported components

Must correctly detect:

export default function Dashboard(){}

const Dashboard = () => {}

export const Dashboard = () => {}

export default memo(Dashboard)

export default forwardRef(...)

Regex remains fallback only.

Nested routes

Regex fallback remains.
